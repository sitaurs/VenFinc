# DESIGN-01 — 90 Screen IDs, Routes & Responsive Reference Map

**Audit:** keempat ZIP mengandung 90 PNG mobile + 90 PNG web untuk **90 screen IDs** (termasuk 6 flow forms, 4 special states, 2 dark anchors). Layar bukan aplikasi berjalan; semua data contoh harus diganti oleh data benar. Asset full PNG tidak disalin ke ZIP ini; ekstrak 4 original ZIP ke `reference-design/full/VenFinance_UIUX_ImageGen/` sebelum code visual QA.

## Kontrak route dan shell

- `PUB`: public shell, `AUTH` login shell, `ONB` wizard, `FIN-UI/FLOW/REV/SET` authenticated app shell, `ADM` admin shell, `SYS` superuser shell.
- `FLOW` sering berupa sheet/dialog mobile & route-backed desktop; path menunjukkan deep link intent, bukan kewajiban render halaman berdiri sendiri.
- `STATE` dan `DARK` **bukan route mandiri**; mereka merepresentasikan varian dari screen yang sudah ada.
- Setiap route wajib punya session/role gate + loading/empty/error; jumlah 90 screens tidak berarti 90 komponen aplikasi yang terpisah.

## QA per screen

1. Gunakan kedua raster mobile/web **asli** sebagai target visual. Lakukan capture Playwright pada viewport referensi + 360/390/768/1024/1440/1920.
2. Cek header/logo, hierarki saldo/budget, menu aktif sesuai route, komponen, copy, font, spacing, kontras dan visual state.
3. Tentukan jika angka bitmap sintetis tidak logis (mis. nominal masuk saldo ganda) → jangan menyalin kesalahan contoh ke perhitungan produksi.
4. Uji per layar: authorized, unauthenticated, wrong role, loading, empty, error, offline (jika sesuai), ID/EN, dark.
5. Gambar saja tidak membuktikan interaksi; setiap CTA harus punya route/aksi teruji. Catat screenshot actual vs sumber dan alasan setiap deviasi.
